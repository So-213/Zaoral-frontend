## 3. API設計

### 認証API

#### `GET/POST /api/auth/[...nextauth]`
- **機能**: NextAuth認証ハンドラ
- **認証方法**: 
  - Google OAuth
  - LINE OAuth
  - テストユーザー（開発環境用）
- **セッション戦略**: JWT
- **アダプター**: PrismaAdapter

### プロジェクト管理API

#### `POST /api/projects`
- **認証**: 必須
- **リクエストボディ**: 
  ```json
  {
    "slug": "string (6文字のランダム文字列、フロントエンドで生成)",
    "type": "message (現在はmessageのみ有効)",
    "name": "string (必須、プロジェクト名)",
    "message": "string (必須、メッセージ本文)"
  }
  ```
- **レスポンス**: `201 Created`
  ```json
  {
    "id": "string",
    "slug": "string",
    "user_id": "string",
    "user_name": "string",
    "type": "message",
    "name": "string",
    "created_at": "DateTime",
    "expires_at": "DateTime (作成日時+31日)",
    "projectMessage": {
      "message": "string"
    },
    "projectPicture": null
  }
  ```
- **機能**: 
  - プロジェクト作成
  - 有効期限は自動で31日後に設定
  - プレミアムプラン以外の場合、残機（left_projects）を1減らす
  - 残機が0以下の場合、作成不可（403エラー）
- **バリデーション**: 
  - slug、type、name、messageは必須
  - typeは`message`のみ有効（`picture`は一時停止中）
- **トランザクション**: プロジェクト作成と残機減算を同一トランザクションで実行

#### `DELETE /api/projects?id=:id`
- **認証**: 必須
- **クエリパラメータ**: `id` (プロジェクトID)
- **レスポンス**: `200 OK`
  ```json
  {
    "message": "プロジェクトが正常に削除されました"
  }
  ```
- **機能**: プロジェクト削除
- **権限チェック**: 所有者のみ削除可能
- **カスケード削除**: 関連するProjectMessage/ProjectPictureも自動削除
- **S3削除**: pictureタイプの場合はS3からも画像を削除（現在は未使用）

#### プロジェクト一覧取得
- **実装方法**: APIエンドポイントではなく、`/dashboard`ページで直接Prismaを使用
- **認証**: 必須（ページレベル）
- **取得条件**: 
  - ログインユーザーのプロジェクトのみ
  - 作成日時の降順でソート
- **フィルタ**: 有効期限切れ1ヶ月後以内のプロジェクトのみ表示（実装は未確認）

### アカウント管理API

#### `PUT /api/account/plan`
- **認証**: 必須
- **リクエストボディ**: 
  ```json
  {
    "plan": "FREE" | "PREMIUM"
  }
  ```
- **レスポンス**: `200 OK`
  ```json
  {
    "message": "プランをFreeに変更しました",
    "plan": "FREE"
  }
  ```
- **機能**: ユーザーのプランを変更
- **バリデーション**: 
  - planは`FREE`または`PREMIUM`のみ
  - 既に同じプランの場合はエラー（400）

### 画像アップロードAPI（一時停止中）

#### `POST /api/projects/upload`
- **状態**: 一時停止中（picture型プロジェクトが一時停止中されたため）
- **レスポンス**: `400 Bad Request`
  ```json
  {
    "error": "画像型プロジェクトは現在利用できません"
  }
  ```

### 定期実行タスク（Cron）

#### `GET /api/cron/cleanup-expired-projects`
- **認証**: Vercel CronのAuthorizationヘッダー（Bearer token）
- **スケジュール**: 毎月1日 0:00（`0 0 1 * *`）
- **機能**: 期限切れプロジェクトの自動削除
- **削除条件**: `expires_at`が31日前以前のプロジェクト
- **レスポンス**: `200 OK`
  ```json
  {
    "message": "期限切れプロジェクトの削除が完了しました",
    "deletedCount": 0,
    "deletedAt": "2025-01-15T00:00:00.000Z"
  }
  ```
- **カスケード削除**: 関連するProjectMessage/ProjectPictureも自動削除

### 公開機能（Zaoral_backend3）
- `GET /p/:slug`
  - **認証**: 不要（公開エンドポイント）
  - **機能**: 公開プロジェクト取得（有効期限内のみ）
  - **詳細**: 別バックエンドサービス（Zaoral_backend3）にて実装

## 4. データベース設計

### 主要テーブル

#### User（ユーザー）
- `id`: ユーザーID（CUID）
- `name`: ユーザー名
- `email`: メールアドレス（ユニーク）
- `emailVerified`: メール認証日時
- `image`: プロフィール画像URL
- `plan`: プラン（FREE / PREMIUM）
- `left_projects`: プロジェクト作成残機（デフォルト: 3）
- `stripe_customer_id`: Stripe顧客ID（将来の課金用）
- `created_at`: 作成日時
- `updated_at`: 更新日時

#### Project（プロジェクト - 基底テーブル）
- `id`: プロジェクトID（CUID）
- `user_id`: ユーザーID（外部キー）
- `user_name`: ユーザー名（スナップショット）
- `type`: プロジェクトタイプ（`message`のみ有効、`picture`は一時停止中）
- `slug`: スラッグ（ユニーク、6文字のランダム文字列）
- `name`: プロジェクト名
- `created_at`: 作成日時
- `expires_at`: 有効期限（作成日時+31日）

#### ProjectMessage（メッセージ型プロジェクト）
- `project_id`: プロジェクトID（外部キー、主キー）
- `message`: メッセージ本文（TEXT）

#### ProjectPicture（画像型プロジェクト - 一時停止中）
- `project_id`: プロジェクトID（外部キー、主キー）
- `s3_key`: S3のオブジェクトキー
- **注意**: このタイプは現在一時停止中で、新規作成不可

#### Account（認証アカウント）
- NextAuth.js用のアカウント情報テーブル
- Google/LINE認証情報を保存

#### Session（セッション）
- NextAuth.js用のセッションテーブル

#### Subscription（サブスクリプション）
- Stripeサブスクリプション情報（将来の課金用）

## 5. ビジネスロジック

### プロジェクト作成制限
- **FREEプラン**: 
  - デフォルトで3回のプロジェクト作成残機（`left_projects`）
  - プロジェクト作成時に残機を1減らす
  - 残機が0以下の場合、作成不可
- **PREMIUMプラン**: 
  - 残機制限なし（無制限）
  - プロジェクト作成時に残機を減らさない

### プロジェクト有効期限
- すべてのプロジェクトは作成日時から31日間有効
- 有効期限切れ後、31日経過したプロジェクトは自動削除（Cron）

### プロジェクトタイプ
- **message**: メッセージ型プロジェクト（現在唯一有効なタイプ）
- **picture**: 画像型プロジェクト（一時停止中、新規作成不可）

## 6. セキュリティ

### 認証・認可


#### 実装場所
- **JWT認証設定**: `src/lib/auth.ts`
  - NextAuth.js v5の設定（JWTセッション戦略、コールバック）
  - Google/LINE OAuthプロバイダー設定
  - JWTトークンに`userId`を格納するコールバック実装
- **認証ハンドラ**: `src/app/api/auth/[...nextauth]/route.ts`
  - NextAuthハンドラのエクスポート（GET/POST）
- **APIルート認証**: `src/lib/api-helpers.ts`の`requireAuth()`関数
  - 各APIルートで`requireAuth()`を呼び出して認証チェック
  - 認証されていない場合は401エラーを返す
  - 実装例: `src/app/api/projects/route.ts`、`src/app/api/account/plan/route.ts`
- **ページレベル認証**: `src/middleware.ts`
  - `/dashboard`、`/create`、`/account`へのアクセス制御
  - **注意**: 現在はVercelのmiddlewareサイズ制限によりコメントアウトされている（代わりに`requireAuth()`を手動で使用）

### データバリデーション
- リクエストボディの必須フィールドチェック
- プロジェクトタイプの有効性チェック
- 残機チェック（FREEプラン）

#### 実装場所
- **バリデーションヘルパー**: `src/lib/api-helpers.ts`の`validateRequired()`関数
  - 必須フィールドの存在チェック（空文字列も無効）
  - エラー時は400ステータスでエラーメッセージを返す
- **プロジェクト作成API**: `src/app/api/projects/route.ts`
  - `slug`、`type`、`name`、`message`の必須チェック（`validateRequired()`使用）
  - プロジェクトタイプの有効性チェック（`message`のみ有効、`picture`は一時停止中）
  - FREEプランの残機チェック（`left_projects <= 0`の場合403エラー）
- **プラン変更API**: `src/app/api/account/plan/route.ts`
  - `plan`フィールドの有効性チェック（`FREE`または`PREMIUM`のみ）
  - 既に同じプランの場合のチェック（400エラー）
- **プロジェクト削除API**: `src/app/api/projects/route.ts`
  - 所有者権限チェック（`checkProjectOwnership()`関数使用）
  - プロジェクトが存在しない、または所有者でない場合は404エラー

## 7. 設定・環境変数

### 必須環境変数
- `DATABASE_URL`: PostgreSQL接続URL
- `DIRECT_URL`: PostgreSQL直接接続URL（Prisma用）
- `NEXTAUTH_SECRET`: NextAuth秘密鍵
- `AUTH_GOOGLE_CLIENT_ID`: Google OAuth クライアントID
- `AUTH_GOOGLE_CLIENT_SECRET`: Google OAuth クライアントシークレット
- `AUTH_LINE_ID`: LINE OAuth クライアントID
- `AUTH_LINE_SECRET`: LINE OAuth クライアントシークレット
- `NEXT_PUBLIC_PROJECT_DISPLAY_URL`: プロジェクト表示用URL（デフォルト: `https://mipzrl.vercel.app`）

### オプション環境変数
- `AWS_ACCESS_KEY_ID`: AWS S3アクセスキー（picture型使用時、現在は未使用）
- `AWS_SECRET_ACCESS_KEY`: AWS S3シークレットキー（picture型使用時、現在は未使用）
- `AWS_REGION`: AWSリージョン（デフォルト: `ap-northeast-1`）
- `S3_BUCKET_NAME`: S3バケット名（picture型使用時、現在は未使用）
- `CRON_SECRET`: Cronエンドポイント認証用シークレット

## 8. デプロイメント

### Vercel設定
- **フレームワーク**: Next.js
- **ビルドコマンド**: `npm run build`（`prisma generate`を含む）
- **インストールコマンド**: `npm install`
- **関数タイムアウト**: 30秒（`app/api/**/*.ts`）
- **Cronジョブ**: 毎月1日 0:00に期限切れプロジェクトを削除

### データベースマイグレーション
- Flywayを使用。アプリから独立したDB作成プロセス（`docker-compose` の `migrate` サービス）が適用する
- マイグレーションファイルは`ops/db/migration/`に保存
- アプリはDDL権限を持たない（`zaoral_app` ロールで接続）。適用は `zaoral_migrator` のみ
- `prisma/schema.prisma` はPrisma Clientの型生成用で、DBへの適用には使われない
- 詳細は [ops/db/README.md](../ops/db/README.md) 参照
